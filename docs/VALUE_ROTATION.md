# 月度价值择优与持仓轮换（0.7.0）

全市场股池是候选库，实际持仓单独构建。默认候选数量无限制，组合最多10只，每月复查最新已知财务和价格。
默认配置仍用50/200双均线过滤趋势，再从通过价值与趋势条件的候选中按价值评分择优；
纯价值轮换可将 `strategy.name` 改为 `buy_hold`，保留 `[value]`、`[portfolio]` 和月度调仓。
`buy_hold` 在这套配置下只提供候选等权信号，价值层与持仓层仍会定期卖出和补位。

## 月度运行规则

1. 每月首个可观测交易日收盘，使用当时价格与 `known_on <= 当日` 的年报重新筛选全市场；
   PE>25、PB>3、盈利质量不达标、ST等不合格者退出候选池。股价上涨本身不是卖出理由，须按配置判断估值。
2. 对通过价值条件及所选价格策略的股票排序。旧持仓仍合格且位于排名前15时优先保留，
   新仓从排名更高的未持有候选补入，实际目标最多10只。排名缓冲避免因小变动反复更换，设 `rank_buffer=0` 可严格按前10轮换。
3. 估值或质量不达标者不能用排名缓冲保留；旧持仓跌出保留排名或不再满足所选价格策略，也会产生退出目标。
   没有合适替补时留现金，不为凑满数量降低筛选条件。
4. 收盘产生目标，下一个实际观测交易日开盘先卖后买。停牌、跌停、参与量或其他限制使旧仓未能完全退出时，
   仍占用持仓名额和资金；不会假定已经卖出而超额建仓。未成交目标不盲目重试，到下一次调度/风险事件重新评估。
5. 盘后风险检查仍每日进行，可在月度复查之外止损或触发回撤熔断；没有定期选择触发时，单股风险退出不自动买入替补。

估值、盈利质量和价值评分的具体口径见 [VALUE.md](VALUE.md)。财务采用年报而非TTM，且需核对每股口径与公司行动。
股票池、价值评分、当前持仓和下单结果是独立层次，目标持仓不代表已成交持仓。

```toml
rebalance = "monthly"

[value]
# 其他财务参数见完整示例；这是候选股池数量，不限制实际扫描范围。
fundamentals = "fundamentals.sqlite3"
top_n = "all"
max_per_industry = "all"
frequency = "monthly"

[portfolio]
max_positions = 10
rank_buffer = 5
rebalance_tolerance = 0.20
minimum_trade_value = 5000
```

`max_positions` 是实际资金持仓预算，不截断全市场候选或下载范围。每个入选股票按所选策略在入选组合内重新归一化，
再应用单股15%、总仓90%等风险限制；少于10只合格者时不保证满仓。
新仓至少能承担一个交易单位，资金不足的候选会被跳过；数量、现金、涨跌停及成交量仍约束开盘实际成交。

## 整手与小额调仓修正

启用 `[portfolio]` 时，对**买卖差额**做整手取整；当前100股、计算目标99点几股，保留100股，
不会先把目标持仓取整成0而整仓卖出。一般加减仓还需同时通过最低交易金额和目标相对偏离20%的容差，
成交量或资金限额缩小订单后也重新检查最低金额。
明确清仓（目标权重为0）不受上述容差和金额限制，包括不足一手的可卖尾股。

可人工调用的纯函数 `plan_rebalance(..., policy=PortfolioSpec(...))` 使用同一取整逻辑，
并要求确认旧仓退出后的新账户快照才释放持仓名额；不会用未成交卖单释放买入预算。
这不启用实盘，不自动访问私有账户。未配置 `[portfolio]` 的旧实验继续使用原有语义，不能把其旧结果当成本版本改进后的组合表现。

每份JSON报告增加 `portfolio_decisions`：决策日期、候选数、选择/保留/新增/退出股票、排名、退出原因和资金不足跳过原因。
例如 `exit_reasons[股票]="valuation_filter"` 表示价值阈值不再满足，`rank_deterioration` 表示排名跌出缓冲区。
实际成交与持仓退出区间仍在 `fills` 和 `activity`；风控事件在 `events`。

## 可复现的月度轮换审计

```sh
.venv/bin/emt quant rotation-demo --directory .quant/rotation-audit
.venv/bin/emt quant backtest --config .quant/rotation-audit/strategy.toml --output .quant/rotation-audit/report.json
```

目录已存在时拒绝覆盖，换新目录即可复现。数据全部标为 `SYNTHETIC`，价格跳跃和风险设置只用于功能验证，不是收益证据。

| 决策 | 条件 | 下一交易日实际执行 |
| --- | --- | --- |
| 2024-01-02 | A价值评分最优 | 01-03买A |
| 2024-02-01 | A的PE升至30，超过25；B最优 | 02-02卖A、买B |
| 2024-03-01 | B的PE升至30，超过25；C最优 | 03-04卖B、买C |
| 2024-04至06 | C持续合格，仓位偏移很小 | 保留C，无额外交易 |

审计共3个成交日、2个换股日、5笔成交，验证“第二个月估值过高卖出、择优补位”，不能用其中人工价格上涨推断投资收益。

## 回测与升级

```sh
.venv/bin/emt quant compare --config examples/quant/full_market.toml --start 2025-01-02 --end 2026-10-28 --directory .quant/value-rotation-comparison
bash scripts/run_value_daily.sh
```

比较命令支持七策略和月/周/日频率，并保留独立的持仓选择层。
历史参考固定**当前候选名单及当前价值评分**，存在未来成员、未来因子及幸存者偏差，只用于诊断执行成本和观察行为，
不是真实历史月度动态价值选股收益。`frozen-current-ranking.json` 保存参考用的评分日期与数据。
可信长期收益仍需积累或导入真正有时点保证的历史财务、状态、目录和行情可用记录，不会回填公告日期冒充已知历史。

新默认账本为 `.quant/full-market-rotation-paper.sqlite3`，报告为 `full-market-rotation-paper.json`，
旧 `.quant/full-market-paper.sqlite3` 与研究报告保留。新持仓参数纳入指纹，拒绝复用旧参数账本；
原ETF/未配置持仓层的旧实验指纹保持兼容。系统定时任务仍需外部调度器，实盘保持关闭。

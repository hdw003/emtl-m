# 沪深北全市场价值选股（0.6.0）

默认入口为 [full_market.toml](../examples/quant/full_market.toml) 和 `scripts/run_value_daily.sh`。
不再手写股票清单，不设200只候选上限；价值配置 `top_n="all"`、`max_per_industry="all"`，所有通过条件的股票入池。
金融、ST、低质量、高估值、上市不足一年、缺资料、停牌或流动性不足仍会明确落选。扫描全市场不等于买下全市场。

## 全量扫描和恢复

```sh
uv sync --locked --extra tests
.venv/bin/emt quant market-scan --config examples/quant/full_market.toml --output .quant/full-market-scan.json
bash scripts/run_value_daily.sh
```

证券目录来自东方财富 `RPT_F10_BASIC_ORGINFO`，覆盖上海、深圳、北京股票；全量下载全部分页，
检验声明的总页数、总行数、重复记录和三个交易所覆盖。申报未上市代码不计入已上市范围，缺失上市日期单列。
已退市历史证券可能仍在目录中，当前无有效行情者明确落选，不能把目录行数当成当前活跃股票总数。

年报批量采集最近两个完整年度，逐证券取最新已公告年报；使用年报基本EPS、每股净资产、加权ROE、经营现金流/股与负债率。
当前全量收盘价来自 `RPT_VALUEANALYSIS_DET`。财务与估值初筛对整个目录逐只执行，然后对**全部通过者**下载历史日线并做流动性检查，
不采用排名前N名才下载的捷径。过去已下载股票继续更新日线，供退出持仓使用。

默认日线显式使用腾讯 raw day，按自然年请求，不接收 qfq/hfq 替代成交价格，不自动混用价格源。
自动归档已实施分红送转并标注于未复权日线。缺除息日行情时延至下一实际观测日应用，报告列出延迟记录；
分红按税前数额、除息日入账，未模拟实际派息日、个人分红税、配股和复杂重组。
非整数送股向下取整，不虚构现金补偿。科创板按200股整倍数、其他股票按100股整倍数模拟，
比实际某些板块允许的申报增量更保守；科创/创业板20%、北交所30%、主板10%涨跌停模型，未覆盖所有特殊交易状态。

`workers=8` 是并发数，`page_size=500` 是单页大小，二者**都不是股票数量上限**。
每个成功请求立即存入带校验和的SQLite缓存，失败任务全部尝试后报告，重跑复用已完成请求。
网络或结构校验失败的运行标为 `incomplete`，不发布部分名单或部分股池，也不继续模拟盘。
缺年报、缺当前行情、历史不足等可判断的数据覆盖问题逐证券记录，不伪装成网络成功的完整数据。

扫描报告包含 `registry_count`、`financial_count`、`priced_count`、`prequalified_count`、`selected_count`、
完整排名、每个已上市代码的 `screening_status`、交易所覆盖和公司行动限制。
`value-pool` 是基于本地已下载行情的预览；全市场覆盖审计请看 `market-scan` 输出。

## 动态股池与长期维护

每天采集全部目录、财务与价格；价值股池默认每月首个观测交易日重排，也可改季度；
股票名单与首次可用历史数据按真正观察日生效，新增股票不倒填进过去的模拟持仓。
全市场模式无需修改固定 `[[instruments]]`；参数发生语义变化仍需新建模拟账本。
首次有可用财务数据可月中初始化，ST/非活跃/财报过期/移出目录会提前剔除。

价格策略默认周调仓，股池变化与风险退出可以额外触发交易，因此实际成交频率可能更高。
`strategy.top_n` 是动量轮动策略的持仓集中度参数，与全市场扫描或价值股池上限无关；默认双均线策略不按数量截断趋势合格者。
资金、整手、单股15%与总仓90%风险预算仍约束真实可买入数量。100万元等权分散到几百只股票时，最低佣金和整手偏差可能很显著。

`daily` 对全市场配置执行全扫描、重新加载新目录、再运行模拟盘；不调用实盘接口。
SQLite账本校验当时已知目录、财务、价格与成交。新股票的预热历史在首次可用日加入校验，
允许正常扩展股票覆盖，旧实验的已知数据修订则拒绝静默覆盖。实盘适配器默认关闭，北交所实盘路由明确拒绝。

```cron
CRON_TZ=Asia/Shanghai
30 16 * * 1-5 cd /workspace/emtl-m && bash scripts/run_value_daily.sh >> .quant/full-market-daily.log 2>&1
```

以上为部署示例，未自动安装系统定时任务；需持续在线主机或外部调度器，并继承网络代理与CA环境。
非交易日没有新行情时会失败退出，不虚构当日K线。监控退出码、`incomplete`、数据新鲜度、空池和 `halted`。

状态保存在 `.quant/full-market.sqlite3`（原始响应/目录/历史可用日/断点）、`full-market-fundamentals.sqlite3`、
`full-market-daily.csv`、`full-market-paper.sqlite3` 与JSON报告。用SQLite在线备份接口备份数据库，CSV与配置同时保存。
原始请求按日期留档，磁盘会持续增长，应归档、监控容量；未提供自动删除历史证据的清理任务。
升级先运行测试、在副本上验证重放；若历史修订被拒绝，保留旧账本并明确新建实验，不能删除检查绕过。

## 回测和频率对比

```sh
.venv/bin/emt quant compare --config examples/quant/full_market.toml --start 2025-01-02 --end 2026-10-28 --directory .quant/full-market-comparison
```

生成七策略 × 月/周/日调仓的JSON、汇总CSV、当前完整股池CSV及 `REPORT.md`。
同时生成严格时点结果 `actual-*.json`，只从首次财务观测起计算；新建系统第一天尚无下一开盘成交，年化收益不可用。
历史参考 `biased-static-*.json` **固定当前股池回看历史，存在未来成员与幸存者偏差，不是历史动态价值策略收益验证**。
要评估真实历史动态选股，需要另行导入完整的当时财务版本、目录、状态和行情可用历史；当前名单不能填回过去。

每份报告 `activity` 分开统计：计划信号频率、有成交的日期、从零建仓次数、完整清仓次数、
同日既有建仓又有清仓的换股日期、配对替换数量、已结束持仓的交易日/自然日均值及未结束持仓数量。
首次建仓不算换股；同一股票加减仓算成交调仓，不能冒充替换股票；未结束持仓不混入已结束持仓均值。

实测数据范围与收益表见 [FULL_MARKET_VALIDATION.md](FULL_MARKET_VALIDATION.md)。

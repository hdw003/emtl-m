# 项目开发摘要

更新日期：2026-10-29（Asia/Shanghai）。当前版本：**0.7.0**。功能基线提交：[`e5c182e`](https://github.com/hdw003/emtl-m/commit/e5c182e)。

本文件供后续维护和开发交接使用；行情数量、测试数量与回测结论均注明当前验证范围，不代表每日自动更新。

## 目标与当前交付

项目原有功能是东方财富证券网页交易协议的现代Python客户端，提供行情、登录、资产及委托查询、买卖和撤单接口。
本轮开发在此基础上集成A股及ETF日线研究、回测、模拟盘与价值选股能力，交付阶段为**回测和模拟盘，实盘由用户另行手动启用**。

当前主流程：

1. 全量发现沪深北股票，获取公开财务和价格，不设候选数量上限。
2. 使用当时已知财务和价格筛选价值候选库，默认不限制入池数量或行业数量。
3. 按月从候选库择优构建实际组合，默认最多10只；候选库和实际持仓分别管理。
4. 持仓估值过高、质量不达标、排名明显恶化或不再满足价格策略时，产生退出目标，再从合格候选中择优补位。
5. 收盘决策，下一实际观测交易日开盘先卖后买；没有合适替补时留现金，退出受阻时不预支名额和资金。

默认价格策略为50/200双均线。将策略改为 `buy_hold` 并保留价值层和持仓层，可进行纯价值排名轮换。
其余内置策略为时间序列动量、动量轮动、通道突破、布林均值回归和逆波动率，共七类。

重要设计纠正：0.6.0的部分策略将整个候选库分摊为等权目标，百万资金分散数百只股票后，
整手与最低佣金造成大量不经济交易。旧算法先对目标总持仓取整，可能将“当前100股、目标99点几股”取整成0并误清仓。
0.7.0独立选择实际持仓，对交易差额做整手取整，并增加调仓容差和金额门槛；明确清仓不受这两项门槛限制。
未配置 `[portfolio]` 的旧实验保留原语义和指纹，旧报告不能当成新组合的表现。

## 当前默认参数

完整配置：[examples/quant/full_market.toml](../examples/quant/full_market.toml)。

| 项目 | 默认值 |
| --- | --- |
| 候选与价值池数量 | 无上限；`top_n="all"`、`max_per_industry="all"` |
| 财务筛选 | 年报PE≤25、PB≤3、ROE≥8%、负债率≤70%、经营现金流/股>0 |
| 其他筛选 | 上市至少365自然日、年报距报告期末≤550天、20日估算日均成交额≥2,000万元；排除ST/非活跃及银行、保险、证券 |
| 评分 | 估值与质量横截面评分：盈利收益率方向40%、账面收益率方向30%、ROE方向30% |
| 定期复查 | 价值池和默认组合每月首个观测交易日收盘复查；首次取得可用财务可月中初始化 |
| 实际持仓预算 | 最多10只，可配置；不会截断候选扫描 |
| 保留排名缓冲 | 5名；仍合格的旧仓在前15名内优先保留；设为0可严格按前10名轮换 |
| 一般调仓 | 相对目标偏离达到20%且交易金额至少5,000元；明确退出可低于金额门槛 |
| 仓位与风险 | 单股目标≤15%、总仓目标≤90%；止损12%、跟踪止损15%、回撤20%熔断、冷却20个观测交易日 |
| 成本 | 佣金万三/最低5元，卖出印花税万五，滑点10bps，前一观测日成交量5%参与限制 |
| 数据请求 | 并发8、每页500；均为请求负载设置，不是股票数量限制 |

股池变化、已知ST等安全剔除和每日风险检查可产生月度调度之外的交易。
一般风险退出未触发定期选择时，只退出，不自动补位。目标持仓与实际成交持仓须分别查看。

## 代码结构与接口

主要代码位于 `src/emtl/quant/`：

| 文件 | 职责 |
| --- | --- |
| `market.py`、`market_scan.py` | 全市场目录、完整分页校验、缓存/断点、财务和历史日线扫描、逐证券落选原因 |
| `market_actions.py`、`data.py` | 未复权日线、分红送转标注、CSV读写及公开数据源 |
| `value.py`、`value_ops.py`、`value_provider.py` | 按时点财务、价值筛选与排名、定期候选池、采集和导入 |
| `portfolio.py` | 独立持仓预算、价值排名择优、保留缓冲、交易差额整手与调仓门槛 |
| `strategies.py`、`risk.py`、`engine.py` | 七类价格策略、风险约束、下一开盘撮合与完整回放 |
| `paper.py` | SQLite账本、历史校验、幂等重放和新观察数据接入 |
| `planning.py`、`execution.py` | 纯订单规划、手动启用的实盘适配器、委托日志及歧义结果保护 |
| `report.py`、`activity.py`、`comparison.py` | 权益/成交报告、持仓选择原因、调仓与换股频率、七策略×三频率比较 |
| `config.py`、`cli.py`、`demo.py` | TOML及语义指纹、命令入口、离线功能审计 |

关键公开类型包括 `QuantConfig`、`PortfolioSpec`、`StrategySpec`、`ValueSpec`、`Backtester`、`EMTBroker`。
`plan_rebalance(..., policy=PortfolioSpec(...))` 与组合回测共享整手/金额规则，需确认旧仓退出后才能释放持仓名额。
报告的 `portfolio_decisions` 记录候选数、选择/保留/退出股票、排名和退出原因；`fills` 记录实际成交。
`activity` 区分成交日、从零建仓、完整清仓、同日换股及持仓期限，不把同股加减仓算成替换股票。

## 数据与回测结论的有效范围

2026-10-28行情快照的全量目录含8,371条记录；剔除未上市申报等后审计5,923条已上市证券记录，其中包含历史退市证券。
5,575只具有当前价格，5,770条证券可归一化已公告年报；676只通过财务/估值初筛，全部请求历史日线，最终614只入池（上海308、深圳306）。
北交所参与扫描，但本次公开日线源历史不足，没有进入最终股池。共留存423,641条日线、标注2,490个分红送转日期。
这些是特定日期的数据覆盖结果，不是当前活跃证券总数或实时股池承诺。

财务必须满足 `period_end < published_on < known_on`；自动采集的 `known_on` 为实际观察日，不能倒填为历史公告日。
当前真实留档始于2026-10-28。本次严格时点验证仅有1个有效财务观察交易日、0笔成交，年化不可用。
模拟盘681个回放会话中的前680日属于财务留档前的空仓预热，不能用于证明价值策略获利。

已有21组历史参考固定当前名单和当前价值评分回看2025-01-02至2026-10-28，
**存在未来成员、未来因子和幸存者偏差，不是真实历史动态价值选股收益**。
默认双均线月调仓参考费用由旧配置约6.12万元降至0.63万元；新版参考仍曾触发回撤熔断。
持仓选择和执行方式同时变化，不应将收益差异解释成单一费用因素或可靠的投资收益承诺。
详细数据见 [0.7.0验证记录](VALUE_ROTATION_VALIDATION.md)，0.5/0.6验证记录仅保留为历史版本。

## 已完成的验证

截至功能基线 `e5c182e`：

- 136项自动化测试、lint、格式检查、锁定依赖安装和wheel/sdist构建通过。
- 独立wheel环境运行合成轮换审计：1月建仓A，2月A估值超标后卖A买B，3月B超标后卖B买C；共5笔成交、3个成交日、2个换股日，后续月份无多余交易。
- 验证排名缓冲、候选不变时的月度排名变化、无替补留现金、退出受阻不超买、未来数据不提前影响成交、小额调仓与明确清仓。
- 21组参考回放逐日重建持仓后均不超过10只；新模拟盘重复运行零新增会话，原ETF账本重放也零新增会话。
- GitHub Actions配置覆盖Python 3.12/3.13；以上为本地验证结果，未据此声称远端CI结果已确认。

本开发摘要的整理不改变上述功能或策略参数。

## 启动与维护命令

在仓库根目录，Python要求3.12+：

```sh
uv sync --locked --extra tests
.venv/bin/emt --version
.venv/bin/python -m pytest
.venv/bin/ruff check src tests
.venv/bin/ruff format --check src/emtl/quant tests/quant
uv build
```

首次全市场准备及盘后模拟运行：

```sh
.venv/bin/emt quant market-scan --config examples/quant/full_market.toml --output .quant/full-market-scan.json
bash scripts/run_value_daily.sh
```

脚本通过 `flock` 锁定完整流水线，默认用于上海时间16:00之后；不登录、不下实盘单。
定时任务尚未安装，持续运行依赖在线主机和外部调度器，示例见 [全市场指南](FULL_MARKET.md)。

功能审计与带偏差标注的历史参考：

```sh
.venv/bin/emt quant rotation-demo --directory .quant/rotation-audit-new
.venv/bin/emt quant backtest --config .quant/rotation-audit-new/strategy.toml --output .quant/rotation-audit-new/report.json
.venv/bin/emt quant compare --config examples/quant/full_market.toml --start 2025-01-02 --end 2026-10-28 --directory .quant/value-rotation-comparison
```

合成审计目录拒绝覆盖，复现时选新目录。公开数据使用东方财富财务/目录、显式选择的腾讯未复权日线；ETF保留其配置的数据源。
保留环境代理、CA与TLS验证，不静默混用行情源，不在仓库写入账号凭据。

## 持久化与恢复约定

| 本地路径 | 内容 |
| --- | --- |
| `.quant/full-market.sqlite3` | 原始请求缓存、目录、历史首次可用日、扫描断点 |
| `.quant/full-market-fundamentals.sqlite3` | 追加式财务版本与股池快照 |
| `.quant/full-market-daily.csv` | 历史未复权日线及已标注公司行动 |
| `.quant/full-market-rotation-paper.sqlite3` | 0.7默认组合模拟账本 |
| `.quant/full-market-rotation-paper.json` | 默认组合报告 |
| `.quant/value-rotation-comparison/` | 21组策略频率参考、当前股池/目标CSV及评分证据 |
| `.quant/rotation-audit/` | 合成月度轮换审计 |

`.quant/`、`.venv/`、构建及分析缓存被Git忽略，**推送源码不会备份这些数据和账本**。
数据库应使用SQLite在线备份接口，配置、CSV和原始数据证据也要保存；原始请求按日期积累，需监控磁盘容量。
新配置或已知历史修订若触发账本完整性拒绝，应保留旧账本并新建实验，不得跳过校验或删除记录伪装兼容。
0.6旧账本 `.quant/full-market-paper.sqlite3` 保留，0.7使用独立路径；原ETF实验继续按其配置运行。
